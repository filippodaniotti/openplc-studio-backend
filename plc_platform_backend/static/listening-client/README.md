# Third-Party Modified Version of the webMUSHRA Software

Modified by PLC platform on **2026-10-06**, updated **2026-10-16**. Original AudioLabs copyright and full
license notices are retained. This is not an endorsed AudioLabs/Fraunhofer release.
Upstream commit: `8c353f738aa88fa9dee0dc1aa7d18d2a06441cb5`.

The native, keyboard-accessible renderer replaces the legacy page manager and
synchronous sender, while retaining webMUSHRA's synchronized audio switching,
short fades and looping engine. It consumes the YAML/WAV bundle generated by
HumanCalculator. Anchors are prepared by the core, never synthesized differently
in the browser. Assigned trial/condition orders are immutable and never shuffled
again on reload. Untouched sliders remain unanswered; zero is a valid answer.

The rating surface uses compact, card-free fader columns on one shared scale.
Horizontal guides at 0/20/40/60/80/100 align with the native thumb's score positions;
quality-band labels appear on the left. Focus adds a blurred primary-color glow
centered on the fader rather than outlining a card, with a crisp thumb cue for
keyboard users and an outline fallback in forced-colors mode. The glow respects
reduced motion. Narrow screens scroll the shared grid horizontally, and keyboard
navigation keeps the focused column visible without scrolling the surrounding
study. The reference stays unscored, and stimuli still require playback before
rating or confirming the starting value. Unrated readouts use an accessible
em dash instead of repeating "Unanswered". "Use 50" confirms the initial value;
answered scores show a quieter "Rated" indicator. Columns stay compact (104 px,
92 px on narrow screens) instead of stretching to fill the viewport.

Each Play button has an `aria-pressed` playing state, a tinted pressed appearance
and a motion-reduced audio indicator. Clicking it again pauses. Focus and
playback are separate: moving keyboard focus does not change the playing item.
A shared seek bar and elapsed/total clock stay synchronized across reference and
conditions. Switching preserves the current or pending-seek position, including
while paused; natural end keeps the playhead at the end and clears playing
indicators. A subsequent Play restarts explicitly. Rapid resume/selection requests
cannot leave a stale pause fade or an older async resume in charge of playback.

Saves are complete accumulated rating snapshots, serialized and acknowledged by
FastAPI before advancing/finishing. Exact pending requests and newer edits are
retained in per-tab IndexedDB; bearer invitation tokens are never stored there.
Conflicting revisions require explicit reload, never an automatic overwrite.
The native UI loads only the current trial, at most three files concurrently.
Backend and workers share `LISTENING_AUDIO_BUDGET_MIB` (default **256**, range
1–1024 MiB). Preparation checks every trial's decoded float32 material before
publishing it; explicit and hidden reference share one buffer. Tracks and
repetitions are loaded sequentially, not summed into the budget. Runtime limits
are sent in participant checkpoints, including existing invitations; no study
rewrite is required. The browser checks both estimated and actual decoded size,
allowing a small WAV-header overhead, and reports required/allowed sizes.

`LISTENING_AUDIO_TIMEOUT_SECONDS` (default **120**, range 5–600) bounds each audio
file's fetch/decode operation. Loading progress and an audio retry action are
available, including during volume calibration. Decode operations cannot be
cancelled by Web Audio; aborted workers settle before another load can start.

These limits cover retained decoded audio, **not total browser memory**: encoded
files, decoder work and browser overhead require extra headroom. Raising the
budget cannot guarantee playback on every device. Unsupported playback/storage
capabilities are reported. Chrome/Edge desktop is the primary playback target;
actual audio context rates (including resumed sessions on different devices) are
recorded. Unexpected device resampling can increase decoded size beyond the
48 kHz preparation estimate.

Changes to `MushraAudioControl.js`: remove accidental global references, apply
pending fade-position resets, zero non-looping buffer tails, retain end/paused
seek positions, and cancel pending pause fades on rapid resume. Original source
and all original third-party notices are included in `source.zip`, together with
the deployed modified sources and Angular host. Recipients can obtain it free of
charge at `/api/listening-client/source.zip`. Do not charge copyright-license fees
for this software. Patent licensing, if applicable, remains the user's responsibility.

No PHP, pyMUSHRA, telemetry, demographic questions or separate server is used.
HTTPS (or browser localhost exception) is required. Deployments must protect owner
management APIs independently; participant tokens do not implement owner auth.
Do not gate the participant or free source-download routes behind owner-only access.

Iframe, stylesheet, renderer and modified audio-engine URLs carry the same client
revision (`shared-faders-20261016-2`); bump them together for a new UI release.
Static client responses use `Cache-Control: no-cache` so browsers revalidate
rather than infer a freshness lifetime. If Angular HMR reports a component update
but a fresh HTTP request still returns an older lazy component, restart only the
frontend development server and verify the served iframe URL before rebuilding
images. No invitations or study audio need to be recreated for UI updates.

Regenerate the source archive after edits, from the backend repository:

```sh
python scripts/package_listening_client_source.py --upstream ../webMUSHRA
```
